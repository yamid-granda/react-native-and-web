# Comments

Write as few comments as possible, and keep the ones you write as short as
possible. Code should be understandable by itself — good names and small
functions do the explaining. Only add a comment when it carries information
the code truly can't: a hidden constraint, a workaround for a specific bug,
or a non-obvious reason for an unusual choice. Never restate what the code
already says.

Repo-wide architecture, conventions, and known gotchas belong in this
repo's README (see "Architecture boundaries and known gotchas"), not
repeated as docblocks in individual files — point to it instead of
re-explaining it inline.
